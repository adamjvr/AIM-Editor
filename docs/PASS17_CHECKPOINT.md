# Pass 17 checkpoint — deterministic Python cache hygiene

Pass 17 fixes a build-gate false positive discovered on Rosie after the pinned
Python validation environment became operational.

## Failure observed

The repository checks stopped on an untracked runtime artifact:

```text
FAIL: Python cache artifacts must not be packaged/committed:
  tools/protocol/__pycache__/ion_sysex.cpython-313.pyc
```

The cache had been generated by a previous direct Python invocation.  It was not
repository source and was already covered by `.gitignore`, but the hygiene check
intentionally scans the working tree and therefore caught it.

## Fix

- `tools/clean_python_artifacts.py` removes **untracked** `__pycache__`, `.pyc`,
  and `.pyo` artifacts outside runtime/build roots.
- Tracked Python cache files are an error and are never silently deleted.
- POSIX and Windows build pipelines set `PYTHONDONTWRITEBYTECODE=1` before any
  repository tooling runs.
- Both one-command build pipelines clean stale cache artifacts before the build
  doctor/repository suite.
- `check_repository.py` retains its final working-tree cache check and now also
  explicitly checks `git ls-files` for tracked bytecode.
- CI suppresses bytecode generation and performs the same cleanup in the data
  validation job.

This preserves the strict rule that cache artifacts never belong in a commit,
while ensuring generated local bytecode cannot prevent the real C++ build from
starting.
